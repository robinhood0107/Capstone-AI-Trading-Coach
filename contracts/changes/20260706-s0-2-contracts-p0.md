# S0.2 P0 Contracts

## 변경 이유

S0.2에서 workspace 간 payload와 artifact 교환 기준을 먼저 고정하기 위해 P0 JSON Schema 초안을 추가한다. 런타임 기능, Spring controller, DB migration, Python 서비스 구현은 포함하지 않는다.

## 영향 범위

- Decision Platform: Principle, Order Intent, Risk Decision, Signal payload의 초기 검증 기준으로 사용한다.
- Return Engine: `signal.schema.json`과 `artifact_manifest.schema.json`을 LSTM, rule baseline, backtest artifact export 기준으로 사용한다.
- Experience Dashboard: Spring API와 artifact summary를 소비할 때 동일한 필드명을 기준으로 화면 ViewModel을 설계할 수 있다.
- CI: `uv run python contracts/validate.py`로 valid/invalid examples를 검증한다.

## 호환성 상태

초기 additive 계약 추가이므로 기존 계약과의 breaking change는 없다. REST envelope의 `success`, `data`, `error`는 workspace 간 payload/artifact 계약에서 제외했다.

## 통합 확인

필드명 기준은 `docs/S0_2_P0_계약_통합_필드명_결정.md`에 고정했다. 팀원 B와의 30분 미팅은 새 결정을 만들기 위한 회의가 아니라, Return Engine export가 이 기준을 그대로 따르는지 확인하는 통합 체크포인트다.
