# P1 운영 후속 경계

## KIS·ECOS allowlist 확장

확장은 관리자 local registry의 exact operation, endpoint, projection field, 예상 physical call, credential
mode, TTL, retry와 cost cap을 먼저 고정한다. contract-change와 offline fixture/parser 검증을 통과한 뒤
별도 approval packet으로만 live 실행한다. 일반 사용자는 저장된 projection만 읽고 주문·잔고·계좌 mutation은
0이다. KIS master refresh는 retry 0이며 실패하면 `CATALOG_REFRESH_FAILED_USING_LAST_GOOD`를 유지한다.

## SearXNG known degraded

SearXNG는 Google 월 cap 소진 때만 DuckDuckGo 단일 engine best-effort fallback이다. provider credential
누락이나 Google 실패를 SearXNG로 우회하지 않는다. parser drift, CAPTCHA, 403/429와 `ALL_ENGINES`는
`KNOWN_DEGRADED_NONBLOCKING`이며 CAPTCHA 우회, FlareSolverr와 browser automation은 추가하지 않는다.

## Live order

`LIVE_ORDER=FUTURE_NOT_IMPLEMENTED`다. 1.0.0에는 계좌 조회, 잔고, 주문, 정정, 취소, 체결 통보와 자동
주문 권한이 없다. 향후 구현은 market-data read packet과 분리된 fresh exact approval, 별도 credential
mode, Kill Switch, idempotency, reconciliation, 감사와 사용자 실계좌 확인 gate가 필요하다.

## LightGBM

LightGBM source와 재현 도구는 연구 전용으로 보존한다. production image와 일반 UI에는 넣지 않고 Signal
projection은 DB row 유무와 관계없이 `ABSTAIN/MISSING_EVIDENCE`다. release, activation, daily inference,
RiskDecision과 order wiring은 재도입하지 않는다.
