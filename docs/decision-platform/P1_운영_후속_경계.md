# 자동매매와 운영 경계

## 결론

현재 앱은 24시간 실행할 수 있고 Automation/Journal API, durable schema와 provider-free closed-loop fixture가
있습니다. 그러나 실제 계좌 transport를 호출하는 recurring scheduler와 `./capstone mock start/stop`은 아직
없습니다. 따라서 앱을 켜거나 arm API를 호출한 것만으로 KIS 모의주문이 자동 실행되지 않습니다.

```text
AUTOMATION_CONTROL_API=IMPLEMENTED_EXACT_4
AUTOMATION_CLOSED_LOOP_FIXTURE=PASS_PROVIDER_FREE
AUTOMATION_RECURRING_RUNTIME=NOT_IMPLEMENTED
MOCK_START_STOP_CLI=NOT_IMPLEMENTED
RECURRING_AUTOMATION=DISABLED
KIS_MOCK_CERTIFICATION=NOT_RUN
KIS_LIVE_CALLS=0
```

## 지금 실제로 실행되는 것

- Spring API, 내부 DB 작업 queue, metric, RAG history cleanup
- loopback Return inference process. 실제 Team B pointer가 없으면 fail-closed
- 명시적 `--mock` 뒤 요청을 기다리는 KIS Mock brokerage gRPC
- 기본 OFF인 provider-free data collector/Vertex/automation fixture test

주문을 만드는 cron, Quartz job, systemd timer, heartbeat 또는 08:55 예약은 없습니다. 이번 Owner handoff
단계에서도 새 recurring automation을 만들지 않습니다.

## 이미 구현된 자동운용 경계

- `GET /api/v1/automation/status`
- `POST /api/v1/automation/arm`
- `POST /api/v1/automation/disarm`
- `GET /api/v1/automation/runs`
- owner-scope RLS, CAS version, hashed idempotency, cross-owner 404
- KIS Mock certification, clean release binding, REAL_TEAM_B pointer, Kill Switch와 account digest gate
- quantity 1, long-only, owner별 open lot 최대 1, append-only event
- provider-free restart/duplicate/late/holiday/drift/cancel/reconciliation acceptance

이 구현은 control plane과 deterministic engine을 검증하지만 실제 scheduler/transport wiring 증거는 아닙니다.
Team A/B가 이 Owner runtime을 대신 구현하지 않습니다.

## 실제 activation 전에 필요한 외부 항목

1. Team B actual exact-10과 `REAL_TEAM_B + modelQuality=PASS + mockRuntimeEligible=true`
2. Team A actual production UI 흐름
3. KIS Mock credential과 별도 physical certification 승인
4. certification PASS와 clean current release binding
5. 실제 recurring runtime/CLI를 추가하는 별도 Owner activation 승인
6. 24시간 health와 연속 3개 pinned XKRX session soak

위 조건이 없으면 synthetic/preview를 주문 근거로 승격하지 않고 `PENDING_EXTERNAL_TEAM` 또는
`NOT_RUN`으로 남깁니다.

## 향후 Owner runtime 불변식

- 다음 pinned XKRX session에서만 실행하고 session당 scheduler 1회
- 신규 주문은 09:20 이전, 15:20 미체결은 cancel/reconcile
- quantity 1, session당 submit 최대 1, write retry 0
- unfinished reconciliation이 신규 후보보다 우선
- SELL에는 Vertex call 0, VETO/ABSTAIN에는 order 0, second candidate 0
- manual account drift나 unknown submit/cancel은 HALTED 또는 PENDING_RECONCILIATION
- 자동 fallback, 재주문, 물타기, 강제청산 0
- disarm은 신규 주문만 중지하고 outstanding reconciliation과 volume 보존

## 현재 가능한 KIS Mock certification

별도 exact 사용자 승인과 credential이 있을 때 Owner만 실행합니다.

```bash
./capstone up
./capstone mock configure
./capstone mock doctor

# XKRX 거래일 09:10~15:00 KST
./capstone mock certify --symbol 005930 --quantity 1
```

certification은 현재가 1회, pre-balance, buyable, 지정가 BUY 1주, 즉시 전량취소, execution read,
post-balance와 open-order reconciliation을 bounded하게 수행합니다. token은 0 또는 1, brokerage는 7,
quote는 1, retry는 0입니다. 최종 체결·미체결 0과 pre/post balance digest 동일을 runtime이 검증합니다.

## 인증 결과 보호

`up --mock`은 owner-only canonical request/receipt, input SHA, certified commit/tree, clean worktree와 current
source tree를 다시 검증합니다. 파일 하나라도 바뀌면 source drift로 거부합니다. 이 보호는 KIS Mock
brokerage adapter를 열 수 있는 조건일 뿐 자동운용 시작 권한을 만들지 않습니다.
