# P1 전수 코드리뷰 요약

## 검토 범위와 판정 방식

P1 release review는 tracked Kotlin, Python, SQL, contract/generated 파일과 release workflow,
Dockerfile, Compose, 운영 script를 symbol inventory로 만들고 side effect와 security boundary를
source-to-sink로 수동 추적한다. 생성된 상세 inventory와 command log는 Git 제외 review storage에 두고
이 문서에는 장기간 유효한 구조와 판정 기준만 둔다.

inventory 분류는 다음 여섯 값 중 하나다.

```text
REVIEWED_SIDE_EFFECT
REVIEWED_SECURITY_BOUNDARY
PURE_TESTED
GENERATED_PARITY_VERIFIED
PRESERVED_HISTORICAL
PLACEHOLDER_EXTERNAL
```

현재 review target inventory는 2,081 files, 15,573 symbols다. 분류 합계는
`GENERATED_PARITY_VERIFIED=610`, `PRESERVED_HISTORICAL=84`, `PURE_TESTED=1,131`,
`REVIEWED_SECURITY_BOUNDARY=180`, `REVIEWED_SIDE_EFFECT=76`다. historical migration과 완료 evidence는
수정하지 않고 동작 경계만 회귀 검증한다.

## HTTP에서 저장까지

```text
HTTP route
  -> JWT principal parsing
  -> current DB actor lookup
  -> one-use actor capability
  -> application service
  -> port
  -> JDBC capability function
  -> row/append-only audit/outbox
```

Decision은 `JdbcDecisionPersistenceAdapter`가 `persist_decision_bundle_authorized`를 한 번 호출한다.
DB 함수가 current actor, owner, Principle pin, Kill Switch, idempotency를 확인하고 Decision graph, audit,
idempotency receipt, outbox를 한 transaction에서 쓴다. caller는 independent outbox payload를 공급하지
않는다.

Kill Switch는 `JdbcKillSwitchRepository`가 `transition_kill_switch_authorized`를 호출한다. 함수가 actor
capability, current role/security version, singleton lock, generation CAS를 확인하고 state, invalidation,
transition, audit, redacted outbox를 원자적으로 처리한다. USER/ADMIN stop과 ADMIN-only resume가 no-op에도
같이 적용된다.

## Identity와 DB role 관계

| role | 허용 capability | 직접 base table 경계 |
|---|---|---|
| `decision_app` | Decision/Kill Switch 등 승인된 definer 함수 | Decision graph, Kill Switch, audit direct DML 회수 |
| `decision_identity` | current actor one-use capability 발급 | users broad read/write 없음 |
| `decision_auth` | demo credential/actor identity exact read 함수 | users broad SELECT 없음 |
| `decision_worker` | event-bound claim/materialization/terminal capability | Principle/order/users/Flyway/raw provider 접근 없음 |
| `decision_replay_authorizer` | signed packet와 current ADMIN authorization 기록 | replay execution 없음 |
| `decision_replay` | authorization one-use consume와 append-only replay | arbitrary ID/range update 없음 |
| `decision_demo` | exact synthetic staging/verification | production namespace mutation 없음 |
| `flyway` | migration과 definer ownership | long-running application datasource에 미제공 |

`SECURITY DEFINER` 함수는 `pg_catalog` search path, PUBLIC revoke, exact session role 검사를 사용한다.
audit guard는 application role의 direct INSERT를 막는다. migration owner와 PostgreSQL superuser는 DB
관리 권한상 예외지만 application container에는 해당 credential이 없다.

## Async 관계와 실패 경계

```text
domain transaction
  -> async_job + event_outbox
  -> DB claim or Kafka publish
  -> Python transport-neutral handler
  -> processed_event + materialization + completion outbox
  -> DB commit
  -> DB completion or Kafka manual ack
```

| 실패 | 보장 |
|---|---|
| duplicate poller | `SKIP LOCKED`와 fencing token으로 한 claim만 유효 |
| expired RUNNING | lease audit 뒤 attempt 증가와 새 token; stale token conflict |
| publish 후 DB update 실패 | 재publish 가능; consumer receipt가 materialization 중복 방지 |
| commit 전 crash | offset 미ack으로 재전달 |
| commit 후 ack 전 crash | exact event/hash receipt로 no-op replay |
| same offset/different bytes | poison conflict, domain side effect 0 |
| poison quota full + exact duplicate | duplicate no-op가 quota보다 먼저 실행 |
| unknown/schema-invalid | outbound/domain side effect 0, bounded failure/DLQ record |

## Verification authority 관계

```text
owner host one-shot signer
  -> Ed25519 packet v2
  -> root-owned fixed trust policy + digest-bound public key
  -> current head/tree/operation/cap/TTL validation
  -> Redis and DB authoritative one-use claim
  -> fake transport in tests OR separately approved provider operation
  -> closed-schema report -> semantic/hash checks
```

private key는 Git/image/container/executor env에 들어가지 않는다. executor는 `/etc/capstone-p1/approval-trust-root.json`의 root-owned closed policy만 읽고 `P1_APPROVAL_*` 환경변수를 무시한다. v1 approval packet은 historical bytes이고
신규 실행 authority가 없다. P1 release 검증은 fake transport만 사용하므로 provider physical call은 0이다.

## Complexity와 comment 판정

review trigger는 변경 명령이 아니다. P1 변경분에서 가장 큰 pure/generated hotspot은 contract generator의
schema builders와 `validate_semantics`다. 명시적 key/enum/bound 검사가 contract auditability에 직접
기여하고 characterization coverage가 있으므로 이번 release에서는 쪼개지 않는다. Decision/Kill Switch의
다중 JDBC write는 단일 DB capability 호출로 줄여 실제 원자성과 복잡성을 함께 개선했다.

남긴 주석은 권한, fencing, fail-closed, fixed polling, retirement 이유를 설명하는 것뿐이다. 코드를
그대로 번역하는 주석, debug/commented-out code, 근거 없는 production-ready 문구는 P1
변경분에 두지 않는다. historical V1~V85와 과거 contract-change의 주석은 byte-stable하게 보존한다.

## Release source-to-image 관계

```text
reviewed merge tree
  -> amd64 Spring/Python build labels
  -> Critical/High and secret scan
  -> exact OCI digest push
  -> provenance/SBOM attestation + cosign
  -> digest-pinned DB/Kafka Compose
  -> self-contained docker-save bundle
  -> network-disabled verify/import/E2E
```

review tree, merge tree, image source label, scanned/signed/GHCR/Compose/offline manifest digest가 다르면
release는 fail-closed다. 실제 scan과 bundle lifecycle의 최종 영수증은 exact merge SHA에 결속된 release
기록에서만 완료로 선언한다.
