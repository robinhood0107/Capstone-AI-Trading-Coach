# 최종 배포 확인 현황

## 현재 결론

Docker 앱은 실행되지만 최종 배포 완료 상태는 아닙니다. “구현됨”, “테스트됨”, “현재 실행 중”,
“실제 외부 호출까지 검증됨”을 서로 다른 증거로 판단합니다.

| 확인 항목 | 현재 증거 | 남은 일 |
|---|---|---|
| OpenAPI와 문서 | 48개 전체 1:1 분류, 문서·계약 회귀 29개 PASS | 팀 결과 수신 후 재검증 |
| Dashboard 정적 품질 | typecheck, lint, unit, contract, production build PASS | Team A 기능 12개 구현 |
| Dashboard 브라우저 | 로그인과 주요 화면 Playwright 1개 PASS | API 27개별 method/path/성공 상태 증거 |
| Team B 받은 미리보기 | unit 3개 PASS, 두 번 실행 byte 동일, 외부 호출 0 | 실제 입력 계약과 결과 파일 10개 |
| Team B 실제 결과 적재 | 미구현 | Signal·모델 평가·백테스트 adapter 구현 |
| Spring 주문 안전 경계 | 집중 unit tests PASS | Team A 화면·전체 integration test |
| KIS 모의투자 fake transport | brokerage tests 136개와 source-tree 인증 guard 6개 PASS | 실제 거래시간 수동 인증 1회 |
| 자동 주문 scheduler | 없음 | 지금은 구현하지 않음; 선행조건 뒤 별도 개발 |
| 단일 Compose | 모델 포함 7개 모두 healthy, smoke PASS, 종료 컨테이너 0 | clean clone과 기본 5개 재현 |
| KIS 실계좌 | 코드·설정에서 차단 | 계속 0회 유지 |
| GitHub | 통합 PR은 열려 있음 | 새 문서 commit push, PR CI, merge, main CI |
| 일반 보안·공급망 | 이전 PR HEAD의 필수 CI PASS | 새 HEAD CI와 최종 배포 검사 |

현재 Playwright PASS는 API 27개 완료를 뜻하지 않습니다. 현재 테스트는 로그인과 화면 이동 중심이라
4xx를 모두 잡지 못합니다. Team A 완료 요청서의 강화 조건을 통과해야 Dashboard 연결 완료입니다.

현재 Team B PASS도 받은 PTH/CSV 미리보기의 재현성만 뜻합니다. 실제 Team B 코드가 만든 결과 10개와
입력 provenance, backend 적재가 오기 전에는 모델 통합 완료가 아닙니다.

KIS 모의투자 수동 인증과 자동 주문은 별개입니다. 수동 인증이 PASS해도 프로그램을 켜 두면 자동으로
주문하지 않습니다. 자동매매는 [자동매매와 운영 경계](P1_운영_후속_경계.md)의 선행조건을 모두 끝낸 뒤
별도 계약으로 구현합니다.

```text
CODEX_SECURITY_DEEP_SCAN=NOT_RUN_USER_SCOPED_OUT
KIS_LIVE_BROKERAGE_CALLS=0
```
