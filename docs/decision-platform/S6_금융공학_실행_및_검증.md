# S6 금융공학 실행 및 검증

## 1. 현재 결론

S6.1~S6.5의 offline kernel, 교육 valuation REST, stored snapshot/manual batch는 구현됐다.
S6.6의 event-study와 LightGBM policy replay도 research-only code/schema까지 구현됐지만,
적격 real PIT dataset과 `AVAILABLE` candidate가 없으므로 실제 성과는 `DATASET_UNAVAILABLE`이다.
S6.7의 v2 materializer, V78 append-only storage/reader와 P1 `WARN_ONLY` overlay는 구현됐지만,
production threshold freeze가 없어 운영 mode는 `OFF`이고 activation 완료로 표현하지 않는다.

| 세션 | 구현 상태 | 실증 상태 | 운영 활성화 |
|---|---|---|---|
| S6.1 causal HMM | complete | synthetic/oracle tests | no active Signal/Risk/order wire |
| S6.2 exact GBM Monte Carlo | complete | analytic/synthetic tests | offline only |
| S6.3 AR(1)-OU | complete | synthetic tests | stored snapshot 전 warning port 0 |
| S6.4 BSM/Greeks/IV | complete | independent numeric tests | educational REST only |
| S6.5 manual batch | complete | bounded fixture 4.724초 | scheduler/UI consumer 없음 |
| S6.6 event study/replay | complete | `DATASET_UNAVAILABLE` | research only |
| S6.7 P1 overlay | complete | synthetic freeze + PostgreSQL V78 tests | `OFF/UNAVAILABLE` |

## 2. 계약과 권한

- 생성 권위는 `contracts/generate_s6_contracts.py`와 `s6-contract-lock.v1`이다.
- 과거 v1 schema/catalog/generated bytes와 completion record는 수정하지 않는다.
- `s2-2-system-rule-catalog.v3` rule 15는 95/97.5/99 중 동결된 percentile,
  threshold artifact hash와 config hash를 모두 요구한다. 80 또는 0 fallback은 없다.
- HMM은 report-only이며 active Signal, RiskDecision, order producer가 아니다.
- LightGBM V74 revoke, production early exit, Signal ABSTAIN을 유지한다.
- S6.7은 기존 exact-14 rule 결과 뒤의 별도 overlay다. `OFF`와 `SHADOW`는 판단을 바꾸지 않고,
  `WARN_ONLY`는 fresh `NEW_BUY` trigger의 `ALLOW → WARN`만 허용한다. `ENFORCED`는
  `MODE_NOT_APPROVED`다.
- analyst/RAG/LLM/explanation은 artifact에는 들어갈 수 있지만 semantic input hash 권한은 없다.
- provider, live account, order fan-out은 모두 0이다.

## 3. 저장 경계

- V77은 `financial_engineering_snapshots`와 complete report manifest를 원자 게시한다.
  PostgreSQL publisher는 대상 symbol 전체를 하나의 transaction으로 게시하고, 로컬 report는
  symbol을 단일 safe path component로 encode한 non-promoted staging directory를 완성한 뒤
  atomic replace로만 latest 경계에 드러낸다. 실패한 staging은 즉시 제거한다.
- V78은 `cross_market_risk_snapshots_v2`를 추가한다. `decision_market_writer`는 SECURITY DEFINER
  append function만, `decision_app`은 point-in-time reader function만 실행한다.
- 두 저장 경계 모두 direct update/delete를 금지하고 same identity+same hash는 no-op,
  same identity+different hash는 conflict다.
- S6.7 exposure는 snapshot과 정확히 같은 `availableAt`과 versioned catalog hash를 사용한다.
- explanation hash와 semantic input hash는 서로 다른 authority다.

## 4. S6.6/S6.7 재현 불변식

- event-study block bootstrap은 완전한 event-date row를 단위로 5 XKRX session씩 연속 block을
  샘플링하고 fixed seed로 2,000회 accepted replication을 만든다. usable timeline은
  train/validation/test 60/20/20과 두 5-session purge/embargo를 유지한다. bootstrap CI가 0을
  배제해도 `HISTORICAL_REPLAY`가 아니면 superiority claim은 false다.
- cause conflict와 unsupported rate는 각자의 numerator/denominator를 갖는다. 분모가 0이면
  값을 합성하지 않고 `null + NOT_ESTIMABLE`을 반환한다.
- real LightGBM candidate receipt은 qualification artifact의 `AVAILABLE`과 PIT dataset 가용성을
  별도로 보존한다. 현재는 candidate를 재라벨하지 않고 dataset만
  `DATASET_UNAVAILABLE`, performance claim은 false다.
- S6.7 `availableAt`은 UTC로 정규화하되 microsecond를 보존하고 semantic hash와
  V78 point-in-time reader가 같은 canonical instant를 사용한다. `SHADOW`로 작성한 snapshot은
  runtime config만 `WARN_ONLY`로 바꾸어 권한을 올릴 수 없다.
- Python publisher는 score/threshold를 canonical decimal text로 PostgreSQL에 전달하고 Kotlin은
  95, 97.5, 99를 scale-insensitive하게 비교한다. V78 advisory lock도 client snapshot ID가 아닌
  `(ownerScopeHash, symbol, availableAt)` identity에 결속한다.

## 5. 재현 명령

각 기능의 focused test 뒤 최종 release gate는 다음 순서로 한 번 실행한다.

```bash
uv run --frozen mypy app

uv run --frozen python -m unittest discover -s contracts/tests -v

  --env-file workspaces/decision-platform/spring-api/build/openapi-fixture/openapi.env

./gradlew ktlintCheck build
```

## 6. 성능과 미완료 외부 gate

bounded synthetic fixture에서 exact-31 × 253 stored rows, GBM 10,000 paths를 포함한 S6.5 batch는
4.724초, peak RSS 228,937,728 bytes, snapshot 1,004 bytes, report 971 bytes였다. 이는 production
archive 성능 증거가 아니다. 실제 owner-private archive integration은 `NOT_AVAILABLE`이다.

남은 외부 gate는 최소 3년(목표 5년) PIT dataset, 적격 `AVAILABLE` BUY candidate,
validation-only immutable threshold freeze, 운영 config 승인, UI owner의 실제 consumer 검증이다.
이 gate 전에는 real performance claim, WARN_ONLY operational activation, `ENFORCED`, provider/live/order
권한이 모두 없다.
