# S6 금융공학 실행 및 검증

## 1. 현재 authority

현행 S6 제품 범위는 S6.1~S6.5다. S6.6 research replay/threshold와 S6.7
WARN_ONLY runtime은 무료 strict-PIT 자료 부재로 퇴역했다. 현재 authority는
`s6-contract-lock.v2`와 `s6-capability-disposition.v1`이며 기존 v1 lock,
S6.6/S6.7 schema·fixture·catalog와 V78은 historical-only 재현 자료다.

| 세션 | 상태 | 실증 | 운영 권한 |
|---|---|---|---|
| S6.1 causal HMM | complete | synthetic/oracle | offline report only |
| S6.2 exact GBM Monte Carlo | complete | analytic/synthetic | offline only |
| S6.3 AR(1)-OU | complete | synthetic | offline diagnostic |
| S6.4 BSM/Greeks/IV | complete | REST→gRPC→Python + numeric oracle | educational REST |
| S6.5 manual batch | complete | bounded fixture | manual stored snapshot |
| S6.6 replay/threshold | retired | strict PIT unavailable | none |
| S6.7 WARN_ONLY runtime | retired | valid threshold unavailable | none |

S4.8의 일곱 계약, fixture producer, deterministic scorer, V23/V50 append-only
sanitized evidence storage와 legacy bounded reader는 유지한다. 현재 검증 상태는
`S4_8=VERIFIED_OFFLINE_STORED`이고 Decision, Signal, RiskDecision, order authority는 없다.

## 2. 계약과 저장 경계

- `contracts/generate_s6_contracts.py`는 historical v1 bytes를 계속 검증한다.
- `contracts/generate_s6_retirement_contracts.py`가 current v2 lock과 disposition을 생성한다.
- runtime catalog는 Spring이 실제 사용하는 exact-14 `s2-2-system-rule-catalog.v1`이다.
- `s2-2-system-rule-catalog.v2/v3`, event-study/replay/threshold/risk-snapshot v2 계약은
  historical-only이며 실행 capability가 아니다.
- V77의 financial engineering snapshot/manifest writer와 point-in-time reader는 유지한다.
- V78 table과 기존 row는 감사 이력으로 보존한다. V79는 S6.7 append/read functions와
  runtime role 권한을 제거하고 immutable update/delete trigger는 유지한다.
- HMM active Signal/RiskDecision/order wire, LightGBM production, ENFORCED HOLD/BLOCK은 없다.

## 3. 무료 API strict-PIT 판정

2026-08-21 feasibility probe는 KIS 10회, KRX 1회, ECOS 1회, 공공데이터 2회로
총 14 physical call을 사용했다. retry·비용·live account·order call은 0이다.
과거 값은 일부 조회됐지만 행별 historical `availableAt`을 증명하지 못했으므로
`NON_PIT_HISTORICAL` 참고 자료로만 분류한다.

현재 조회 시각이나 공개 일정을 과거 `availableAt`으로 소급하지 않으며 synthetic fixture를
실제 성과로 표시하지 않는다. 상세 receipt와 재개 조건은
[`S6_무료_API_strict_PIT_가용성_판정.md`](S6_무료_API_strict_PIT_가용성_판정.md)를 따른다.

## 5. 성능과 완료 판정

bounded synthetic fixture의 exact-31 × 253 stored rows, symbol당 GBM 10,000 paths를 포함한
S6.5 batch 기존 측정값은 4.590538초, peak resident 225,538,048 bytes, snapshot 1,004 bytes,
report 1,003 bytes다. 이는 owner archive 성능 증거가 아니라 synthetic regression 기준이다.

owner-private archive와 Dashboard consumer는 S6.5의 별도 외부 검증 대상일 수 있지만,
퇴역한 S6.7의 완료 gate나 활성화 계획은 아니다. provider runtime, live account, order call은 0이며
배포·push·PR·merge는 이 local 검증 범위에 포함하지 않는다.

최종 상태는 다음을 사용한다.

S6_1_TO_S6_5=COMPLETE
S6_6=RETIRED_STRICT_PIT_UNAVAILABLE
S6_7=RETIRED_NO_VALID_THRESHOLD
S6_7_ENDPOINT_E2E=NOT_APPLICABLE
DASHBOARD_S6_7_CONSUMER=NOT_APPLICABLE
PROVIDER_FEASIBILITY_CALLS=14
PROVIDER_RUNTIME_CALLS=0
LIVE_ACCOUNT_CALLS=0
ORDER_CALLS=0
