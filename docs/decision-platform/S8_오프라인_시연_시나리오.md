# S8 offline 시연 시나리오

## 고정 경계

- Compose project는 `capstone-s8-demo`다. 기존 DB, Redis, RAG namespace를 reset하거나 삭제하지 않는다.
- 운영자가 `--brokerage-mode=INTERNAL_PAPER`를 정확히 입력해야만 준비 단계가 열린다. 외부 장애에 따른
  자동 전환은 없다.
- provider, live account, live order physical call은 모두 0이다. RAG answer cache도 꺼 둔다.
- 교차시장 capability는 `RETIRED_NOT_APPLICABLE`이다. 현재 runtime, scheduler, reader, 주문 권한이
  없다는 사실만 교육하며 `WARN_ONLY` 효과나 성과로 표현하지 않는다.
- synthetic backtest는 `decision-platform`이 만든 `SYNTHETIC_FAKE_E2E`이고
  `performanceClaimAllowed=false`다. Team B Return Engine artifact가 아니다.

## 준비와 재현

DB 기본 경로:

```bash
workspaces/decision-platform/demo/s8/run-demo.sh \
  --prepare --adapter=db --brokerage-mode=INTERNAL_PAPER
```

Kafka 선택 경로는 `--adapter=kafka`로만 연다. Kafka profile을 켰다는 사실만으로 Spring adapter가
바뀌지 않는다. generated seed와 receipt는 `artifacts/decision-platform/s8-demo/`에 남고 Git에는
추적되지 않는다.

검증용 deterministic suite:

```bash
workspaces/decision-platform/spring-api/gradlew \
  -p workspaces/decision-platform/spring-api --no-daemon test \
  --tests 'com.capstone.decision.domain.risk.DeterministicAggregatorTest' \
  --tests 'com.capstone.decision.domain.risk.OfflineRuleEvaluationEngineTest' \
  --tests 'com.capstone.decision.DecisionApiIntegrationTest' \
  --tests 'com.capstone.decision.RagV2ApiIntegrationTest' \
  --tests 'com.capstone.decision.AsyncJobApiIntegrationTest' \
  --tests 'com.capstone.decision.KafkaAsyncIntegrationTest'
```
