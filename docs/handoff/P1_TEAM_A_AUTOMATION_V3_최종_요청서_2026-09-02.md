# Team A 최종 요청 — Automation V3

이 문서는 `P1_TEAM_A_DASHBOARD_완료_요청서.md`의 Automation/API 수치만 최신 계약으로
대체한다. 기존 전체 화면 재설계 요청, 디자인 톤, 접근성, 반응형, 실제 데이터 사용 원칙은 그대로다.

## 사용할 계약

- root OpenAPI: exact-75
- Team A acceptance: [`p1-team-a-acceptance.v3` exact-45](../../contracts/catalogs/p1-team-a-acceptance.v3.json)
- typed client: [`p1-team-a-client.v3.ts`](../../workspaces/experience-dashboard/src/shared/api/generated/p1-team-a-client.v3.ts)
- v1 exact-33, v2 exact-38과 기존 generated bytes는 수정하지 않는다.
- catalog 밖 operation, 임의 fetch wrapper, mock 응답, polling은 추가하지 않는다.

## 반드시 완성할 Automation 화면

1. 사용자 정책
   - 보수·균형·공격 프리셋과 `CUSTOM`을 제공한다.
   - 자본 한도, 손절, 익절, 최대 보유 세션, ATR period·multiplier, MODEL_SELL ON/OFF를 모두 표시한다.
   - `maxHoldingSessions=0`은 “무제한”으로 표시하고, version CAS 충돌을 사용자가 이해할 수 있게 보여 준다.
2. AI 설정
   - `aiJudgementEnabled` ON/OFF와 `minimal | low | medium` thinking selector를 제공한다.
   - AI OFF는 “결정론적 결격·RiskEngine만 사용”, AI ON provider 실패는 “이번 run 신규 매수 없음”으로 표시한다.
3. 실행 제어
   - V3 arm은 사용자의 명시적 확인 뒤 한 번만 호출한다. 자동 arm·백그라운드 arm은 없다.
   - 중지는 기존 V1 disarm을 사용한다.
   - arm 409 blocker를 숨기지 말고 `LEGACY_POSITION_PRESENT`, `MARKET_DATA_CATCHUP_REQUIRED`,
     `AI_PROVIDER_NOT_READY` 등 서버 코드를 그대로 설명한다.
4. run과 position
   - runs 목록에서 동적 `runId`로 상세를 연다.
   - position에는 진입가, peak, ATR, trailing stop, 정책 snapshot, expiry를 표시한다.
   - 청산 이유는 `STOP_LOSS`, `ATR_TRAILING`, `MODEL_SELL`, `TAKE_PROFIT`,
     `MAX_HOLDING_SESSIONS`를 서로 다른 상태로 보여 준다.
5. 근거 상세
   - 후보별 status, verdict, score, reason과 source/date/bounded quote/`VERIFIED`를 표시한다.
   - 오래된 근거는 age warning, 미래·위조·미지원 근거는 미사용 상태로 표시한다.
   - Google Search suggestion은 실제 live grounding metadata가 있는 run에만 표시한다.
   - raw provider response, 계좌 식별자, access token은 화면·로그·analytics에 넣지 않는다.

## 인수 시나리오

- 정책 세 프리셋 저장, CUSTOM 전환, version 0 생성, stale CAS 충돌
- AI OFF run의 `AI_NOT_PARTICIPATED`와 provider 호출 0
- AI ON verified evidence run의 후보별 exact quote
- verified veto의 주문 0, unsupported score/veto의 0.5/false 강등
- prompt injection 후보만 ABSTAIN
- ATR history 부족, market-data catch-up, legacy open position blocker
- loading, empty, stale, error, ABSTAIN, HALTED, partial fill, unresolved reconciliation
- desktop/mobile, keyboard navigation, WCAG AA, tabular numerals

## 완료 제출물

- Figma 또는 v0 비교 시안과 최종 선택 근거
- production source·lockfile·테스트·빌드 결과
- exact-45 acceptance 결과와 동적 ID 기반 주요 흐름 캡처
- PR URL, commit SHA, 변경 파일 목록, 남은 blocker

Team A는 후보 집합, 수량, RiskEngine, ATR 계산, 주문 hash를 다시 계산하거나 변경하지 않는다.
