## drift를 어떻게 읽어야 하나

`mock_certification_guard`가 실패한다는 것은 "인증이 실패했다"가 아니라 "**이 코드 상태로는
인증이 확인되지 않는다**"는 뜻이다. 인증은 거래시간(09:10~15:00 KST)에 깨끗한 worktree로 다시
받아야 한다. 그때까지 자동운용 arm은 `CERTIFICATION_INVALID` blocker로 닫혀 있는 것이 맞다.

## 인증을 다시 받으려면 무엇이 있어야 하나

`./capstone mock certify --symbol 005930 --quantity 1`은 아래를 **전부** 요구한다. 하나라도
없으면 credential이나 transport를 만들기 전에 닫는다.

| 조건 | 실패 코드 |
|---|---|
| XKRX 개장일 09:10~15:00 KST | 게이트가 먼저 닫는다 |
| `--symbol 005930 --quantity 1` 명시 | `KIS_MOCK_CERTIFICATION_SCOPE` |
| 워크트리가 완전히 깨끗함(untracked 포함) | `KIS_MOCK_CERTIFICATION_DIRTY_WORKTREE` |
| `feature\|fix\|docs\|infra\|experiment/…` 브랜치 | `KIS_MOCK_CERTIFICATION_BRANCH` |
| 로컬 HEAD == `origin/<branch>` | `KIS_MOCK_CERTIFICATION_UNPUSHED_HEAD` |
| 그 브랜치의 PR이 **OPEN**, non-draft, base `main`, head가 같은 SHA | `KIS_MOCK_CERTIFICATION_PR_NOT_GREEN` |
| 필수 체크 여섯이 전부 `SUCCESS` | 같음 |

필수 체크 여섯은 `Contract schema validation`, `Spring OpenAPI drift`,
`Kotlin ktlint and build`, `Python quality gates`, `Repo hygiene`,
`P1 full-app security gates`다.

**`main`에서는 돌지 않는다.** 영수증이 "어떤 코드가 인증을 통과했는지"를 PR head에 묶기 때문에,
PR이 없으면 묶을 자리가 없다. 병합을 먼저 하면 인증을 받기 위해 브랜치를 다시 내야 한다.
순서는 브랜치 → PR → 체크 초록 → 인증 → 병합이다.

관통 테스트가 증명한 체결은 KIS **모의** 원장 위의 것이다. 실제 증권사 계좌에 닿은 주문은 이
저장소 어디에도 없다.
