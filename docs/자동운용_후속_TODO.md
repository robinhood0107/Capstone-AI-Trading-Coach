# 자동운용 후속 TODO

이번 변경의 고정 50:50은 사용자 승인에 따른 임시 운용 정책이다. 수익률 우위나 모델 비교 검증 완료를 뜻하지 않는다. 구현·데이터 무결성·권한·주문 안전 검증은 아래 연구 TODO와 별개로 수행한다.

현재 구현: 규칙 방향과 별도로 Ridge 1/5/20일 추정치를 표시하고, 같은 기준일·대상일의
LSTM/Ridge 1일 예측을 자동운용에서 고정 50:50으로 사용한다. 화면에 결합값·구성값과
‘비교 검증 예정’(`COMPARISON_PENDING`)을 표시한다. 한쪽 결측·stale 시 신규 매수에 사용하지
않고, 현재 주문 가격과 왕복 비용 뒤 잔여 기대수익을 확인한다. 아래 비교 연구와 결과 UI는
이 구현과 구분되는 미완료 작업이다.

## 모델 비교와 채택 판단 — 미수행

- [ ] 1일 예측의 LSTM 단독·Ridge 단독·50:50 평균을 동일 universe·기간·매매 규칙·비용으로 비교한다. 각 시점 이후의 정답을 학습에 넣지 않고, 선택용 검증 구간과 마지막 평가 구간을 분리한다.
- [ ] 예측 오차·오차 상관과 순수익·최대낙폭·회전율을 함께 측정한다. 가중치 조합을 무수히 탐색하지 않는다.
- [ ] 50:50이 단독 모델보다 악화되면 후속 운영 채택을 재검토한다. 성능 기반 자동 가중치 조정은 별도 작업으로 유지한다.
- [ ] 전략검증 UI에 모델별 비교 결과, 평가 기간, 비용, 모델 버전과 채택 상태를 표시한다. 부진한 값이나 불리한 구간도 함께 보존한다.

완료 조건: 시간순 재현 결과·원본 해시·채택 판단·화면 증거가 서로 일치한다. 현재 모델을 과거 데이터 전체에 적용한 결과는 당시 가능한 예측으로 주장하지 않는다.

근거: [시간순 검증](https://otexts.com/fpp3/tscv.html), [예측 결합](https://otexts.com/fpp3/combinations.html).

## LSTM 1·5·20거래일 — 미구현

- [ ] LSTM도 Ridge와 같은 1·5·20거래일 누적 종가 수익률을 예측하도록 학습·artifact·API·UI를 확장한다.
- [ ] 입력 20거래일과 예측 20거래일을 구분한다. 현재 LSTM은 최근 20일 입력으로 다음 1일만 예측한다.
- [ ] 기간별 정답 완성 시점, 학습 제외 구간, 기업행동, 미래 데이터 혼입을 검증한다.

완료 조건: 세 기간의 독립된 예측·날짜·검증 결과를 제공하고, 화면에도 기간을 명확히 표시한다.

## 실시간 계좌·주가와 UI — 미구현

- [ ] KIS WebSocket `H0STCNT0` 시세와 모의 `H0STCNI9` 주문·체결통보를 서버에서 수신한다. 잔고·예수금 확인은 REST를 결합한다.
- [ ] 이벤트 수신 즉시 서버가 전달하고 다음 렌더링에 반영한다. 표시 때문에 고정 1초·30초를 기다리는 지연을 넣지 않는다.
- [ ] 현재가·등락·평가금액·평가손익·주문 상태를 관련 UI에서 함께 갱신한다. 사용자 입력, 스크롤, 열린 상세 화면을 초기화하거나 전체 화면을 로딩 상태로 돌리지 않는다.
- [ ] 체결 이벤트를 받으면 주문 상태를 반영하고 잔고 확인을 요청한다. 실시간 평가액과 증권사 확인 잔고를 구분하며, 확인되지 않은 값을 확정 잔고로 표시하지 않는다.
- [ ] UI에 연결 상태, 마지막 시세 수신·잔고 확인 시각, 장외·지연·재연결 상태를 표시한다. 이벤트가 없으면 숫자를 임의로 움직이지 않는다.
- [ ] 계좌/앱키당 단일 연결과 중복 구독 방지, 사용자별 전송 격리, 연결 복구 후 누락 대사, REST 공유 유량과 주문·취소 우선순위를 구현한다. 주기 조회는 누락 복구에만 사용한다.
- [ ] 여러 탭, 부분체결·취소·거부, 중복·순서 역전, 연결 단절·복구를 검증한다. 실제 장중 수신부터 UI 표시까지의 지연을 측정하고 증권사 전달 지연과 앱 내부 지연을 분리한다.

완료 조건: 장중 데이터 변화가 즉시 화면에 반영되는 증거, 체결/잔고 대조, 재연결·격리 테스트를 모두 확보한다. 모든 금융 앱이 동일한 전달 지연을 제공한다고 가정하지 않는다.
