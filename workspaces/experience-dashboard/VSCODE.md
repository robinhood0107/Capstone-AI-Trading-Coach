# VS Code에서 테스트하는 법 (프로그래밍 처음인 사람용)

이 문서는 **VS Code 화면에서 뭘 누르는지**까지 하나씩 적었습니다.
컴퓨터를 켜고 이 문서를 따라가면 대시보드가 브라우저에 뜹니다.

전체 소요 시간: **약 15분** (그중 10분은 그냥 기다리는 시간입니다)

---

## 준비물 확인

두 가지만 있으면 됩니다.

1. **VS Code** — https://code.visualstudio.com 에서 다운로드
2. **Node.js** — https://nodejs.org 에서 **LTS** 라고 적힌 버튼 다운로드

둘 다 설치할 때 나오는 선택지는 전부 기본값(Next / 다음)으로 넘기면 됩니다.

> **중요:** Node.js를 방금 설치했다면, VS Code가 이미 켜져 있어도 **한 번 완전히 끄고 다시 켜세요.**
> 안 그러면 아래에서 "node를 찾을 수 없다"는 오류가 납니다. 초보자가 가장 많이 막히는 지점입니다.

---

## 1단계 — 압축 풀기

`experience-dashboard-v2.zip` 파일을 **바탕화면**에 두고 압축을 푸세요.

압축을 풀면 `experience-dashboard-v2` 라는 폴더가 생깁니다.

폴더를 열어서 안에 이런 파일들이 보이는지 확인하세요.

```
package.json
README.md
SETUP.md
src
```

> 폴더 안에 폴더가 하나 더 있고 그 안에 위 파일들이 있다면, **안쪽 폴더**를 쓰면 됩니다.
> `package.json` 이 바로 보이는 폴더가 우리가 열어야 할 폴더입니다.

---

## 2단계 — VS Code에서 폴더 열기

VS Code를 켭니다.

1. 맨 위 메뉴에서 **File** (파일) → **Open Folder...** (폴더 열기)
2. 바탕화면의 `experience-dashboard-v2` 폴더를 선택
3. **Select Folder** / **폴더 선택** 버튼 클릭

> ⚠️ **Open File(파일 열기)이 아니라 Open Folder(폴더 열기)** 입니다.
> 파일 하나만 열면 명령어가 동작하지 않습니다.

### "이 폴더의 작성자를 신뢰합니까?" 창이 뜨면

**Yes, I trust the authors** (예, 신뢰합니다) 를 누르세요.

이걸 누르지 않으면 VS Code가 안전 모드로 열려서 실행이 막힙니다.

### 확인

왼쪽에 파일 목록이 나오고, 맨 위에 `EXPERIENCE-DASHBOARD-V2` 라고 적혀 있으면 성공입니다.

---

## 3단계 — 터미널 열기

터미널은 **명령어를 입력하는 검은 창**입니다. VS Code 안에 들어 있습니다.

메뉴에서 **Terminal** (터미널) → **New Terminal** (새 터미널)

> 단축키: `Ctrl` + `` ` `` (백틱, 숫자 1 왼쪽에 있는 키)
> 맥은 `Control` + `` ` ``

화면 아래쪽에 창이 하나 열리고 이런 글씨가 보입니다.

```
PS C:\Users\내이름\Desktop\experience-dashboard-v2>
```

맥이면 이런 모양입니다.

```
내이름@맥북 experience-dashboard-v2 %
```

**끝에 `experience-dashboard-v2` 가 적혀 있는지 확인하세요.** 다른 폴더 이름이 적혀 있으면 2단계를 다시 하세요.

---

## 4단계 — Node.js가 잘 깔렸는지 확인

터미널에 이걸 입력하고 `Enter`:

```bash
node -v
```

### 이렇게 나오면 정상

```
v22.11.0
```

숫자가 `v20` 이상이면 괜찮습니다.

### 이렇게 나오면 문제

```
node : 'node' 용어가 cmdlet, 함수... 인식되지 않습니다
```
또는
```
command not found: node
```

→ Node.js가 없거나, VS Code를 다시 켜지 않았습니다.
**VS Code를 완전히 끄고 다시 켠 다음** 2~4단계를 다시 하세요. 그래도 안 되면 Node.js를 설치하세요.

---

## 5단계 — 설정 파일 만들기

터미널에 입력하고 `Enter`:

```bash
cp .env.example .env
```

**아무 메시지도 안 나오면 성공입니다.** 프로그램은 성공했을 때 조용한 경우가 많습니다.

### 오류가 나면

Windows에서 `cp` 를 못 알아들으면 이걸 쓰세요.

```powershell
Copy-Item .env.example .env
```

### 확인하는 법

왼쪽 파일 목록에 `.env` 라는 파일이 새로 생겼는지 보세요.
점(`.`)으로 시작해서 목록 맨 위쪽에 있습니다.

---

## 6단계 — 필요한 프로그램 설치 (2~5분)

터미널에 입력하고 `Enter`:

```bash
npm install
```

**여기서 2~5분 걸립니다.** 글자가 계속 올라가는 게 정상입니다. 기다리세요.

### 다 됐는지 아는 법

이런 줄이 나오고 다시 입력할 수 있게 되면 끝난 것입니다.

```
added 400 packages in 2m
```

### 노란 글씨가 잔뜩 나왔는데요?

```
npm warn deprecated ...
```

`warn`(경고)는 **무시해도 됩니다.** 빨간 `error` 만 문제입니다.

### 빨간 error가 났다면

이 두 줄을 차례로 입력해서 다시 시도하세요.

```bash
rm -rf node_modules
npm install
```

Windows PowerShell이면 첫 줄 대신:

```powershell
Remove-Item -Recurse -Force node_modules
```

---

## 7단계 — 실행하기

터미널에 입력하고 `Enter`:

```bash
npm run dev
```

10~30초 뒤 이런 화면이 나옵니다.

```
  ▲ Next.js 15.1.6
  - Local:        http://localhost:3000

 ✓ Ready in 2.3s
```

**`Ready` 가 보이면 성공입니다.**

> 터미널이 멈춘 것처럼 보여도 정상입니다. 서버가 계속 켜져 있는 상태라 그렇습니다.
> **이 터미널을 닫으면 안 됩니다.**

---

## 8단계 — 브라우저에서 열기

터미널에 있는 `http://localhost:3000` 글씨 위에 마우스를 올리고,
`Ctrl` 키를 누른 채 **클릭**하세요. (맥은 `Command` + 클릭)

브라우저가 열립니다.

### 또는 직접 입력

브라우저 주소창에 이걸 입력해도 됩니다.

```
http://localhost:3000
```

---

## 9단계 — 화면이 제대로 떴는지 확인

이 세 가지가 보이면 성공입니다.

1. 왼쪽에 메뉴 (현황 / 내 원칙 / 주문 검토 / 모델 비교 / 백테스트 리포트 / 금융 가이드 / 보고서 캡처)
2. 위쪽에 **노란 띠**로 `합성 fixture ... 실제 성과가 아닙니다`
3. 가운데에 숫자가 들어간 카드들

노란 띠는 **오류가 아닙니다.** 지금 보고 있는 숫자가 가짜라는 걸 알려주는 표시입니다.

# 이제 뭘 테스트하나요

아래 순서대로 눌러 보면서, 각 항목이 **설명대로 동작하는지** 확인하면 됩니다.
그게 이 프로그램의 테스트입니다.

## 테스트 1. 판정 색이 바뀌는가

**주문 검토** 메뉴를 누릅니다.

맨 위 입력 칸에 `dec_demo_warn_000001` 이 들어 있습니다.
이 값을 지우고 아래 값들로 하나씩 바꿔 보세요.

| 입력할 값 | 기대하는 화면 |
|---|---|
| `dec_demo_warn_000001` | 주황색 **WARN 경고** |
| `dec_demo_hold_000001` | 회색 **HOLD 보류** |
| `dec_demo_block_000001` | 빨간색 **BLOCK 차단** |

**확인할 것:** 네 칸짜리 가로 막대(판정 레일)에서 색이 칠해진 칸이 매번 다른 위치로 옮겨 가는가.

## 테스트 2. 형식이 틀리면 걸러내는가

같은 입력 칸에 아무 글자나 넣어 보세요. 예를 들어 `abc123`.

**기대하는 결과:** 입력 칸 테두리가 **빨갛게** 변하고 아래에 안내 문구가 나옵니다.
서버에 요청을 보내지 않고 그 자리에서 막는 것이 정상입니다.

## 테스트 3. 없는 자료를 요청하면

입력 칸에 `dec_없는판정입니다0001` 을 넣어 보세요.

**기대하는 결과:** `해당 자료를 찾을 수 없습니다` 라는 빨간 상자.

**중요한 확인 포인트:** 이 화면이 "데이터 없음" 회색 상자와 **다르게 생겼는지** 보세요.
"자료가 없는 것"과 "불러오기 실패"는 다른 일이라서 다르게 보여야 합니다.

## 테스트 4. 빈칸을 0으로 채우지 않는가

**현황** 메뉴를 누릅니다.

`VaR 95`, `CVaR 95`, `시장 국면` 칸에 **빗금 친 회색 상자**로 `근거 없음` 이라고 적혀 있습니다.

**이게 정상입니다.** 값이 없을 때 `0` 이나 `-` 로 채우지 않고, 없다고 솔직하게 표시하는 것이 이 시스템의 규칙입니다.

마우스를 그 위에 올리면 왜 없는지 설명이 뜹니다.

## 테스트 5. 투자 조언을 거부하는가

**금융 가이드** 메뉴를 누릅니다.

아래 예시 버튼 세 개를 순서대로 눌러 보세요.

| 누를 버튼 | 기대하는 결과 |
|---|---|
| 금 ETF의 롤오버 위험은 무엇인가요? | 설명이 나오고 **출처 연결률 100%** |
| MDD와 Sharpe는 각각 무엇을 말해주나요? | 설명이 나옴 |
| **삼성전자 지금 사도 되나요?** | **거부** — `매수·매도 조언은 하지 않습니다` |

세 번째가 거부되는 게 **핵심 기능**입니다. 고장이 아닙니다.

직접 이런 것도 넣어 보세요.
- `내 계좌 잔고 알려줘` → 계좌 질문 거부
- `날씨 어때?` → 근거를 못 찾았다고 응답

## 테스트 6. 모델이 판단을 미루는가

**모델 비교** 메뉴를 누릅니다.

표에서 **LightGBM** 줄을 보세요. 숫자 대신 `ABSTAIN` 이라는 회색 빗금 표시가 있습니다.

**이것도 정상입니다.** "근거가 없어서 판단하지 않겠다"는 뜻이고, 이럴 때 억지로 숫자를 만들지 않는 것이 이 시스템의 설계입니다.

아래 `종목 코드` 칸에 `005930` 을 넣어 보세요. 현재 신호 화면이 추가로 나옵니다.
`000660` 을 넣으면 네 모델이 모두 값을 내는 화면을 볼 수 있습니다.

## 테스트 7. 원칙 값을 바꿀 수 있는가

**내 원칙** 메뉴를 누릅니다.

- 위쪽 카드 세 개(보수형/균형형/공격형) 중 하나를 클릭 → 아래 값들이 한꺼번에 바뀝니다.
- 슬라이더를 좌우로 끌어 보세요 → 오른쪽 숫자가 실시간으로 바뀝니다.
- 값을 바꾸면 아래쪽 **변경 사항 저장** 버튼이 활성화됩니다.
- **되돌리기** 를 누르면 원래대로 돌아옵니다.

## 테스트 8. 차트가 그려지는가

**백테스트 리포트** 메뉴를 누릅니다.

- 위쪽 카드 4개에 퍼센트 숫자
- 표에 Baseline / Guide / Strict 세 줄
- 선 그래프 3개가 겹쳐진 자산 곡선
- 아래쪽에 초록/빨강 격자무늬(월별 수익률)

격자에서 **빗금 친 칸**은 그 달 데이터가 없다는 뜻입니다.

# 코드를 직접 바꿔 보기

프로그램이 진짜 내 손에서 돌아가는지 확인하는 가장 확실한 방법입니다.

1. 왼쪽 파일 목록에서 `src` → `app` → `page.tsx` 를 더블클릭
2. 이런 줄을 찾으세요 (`Ctrl` + `F` 로 "오늘 상태" 검색)

   ```tsx
   title="오늘 상태"
   ```

3. `오늘 상태` 를 `내 투자 현황` 으로 바꾸세요
4. `Ctrl` + `S` 로 저장
5. **브라우저를 보세요** — 새로고침하지 않았는데도 제목이 바뀌어 있습니다

이게 되면 개발 환경이 완전히 정상입니다.

되돌리려면 `Ctrl` + `Z` 를 누르고 다시 저장하면 됩니다.

# 실수했는지 확인하는 법

코드를 고치다가 뭔가 잘못되면 VS Code가 알려줍니다.

- 잘못된 부분에 **빨간 물결 밑줄**이 그어집니다
- 화면 왼쪽 아래에 빨간색 ⓧ 숫자가 표시됩니다
- 그 숫자를 클릭하면 **PROBLEMS**(문제) 탭이 열리고 뭐가 잘못됐는지 나옵니다

전체를 한 번에 검사하려면 터미널을 하나 더 열어서(터미널 창 오른쪽 위 `+` 버튼):

```bash
npm run typecheck
```

아무것도 안 나오면 문제없다는 뜻입니다.

# 자주 나는 오류

## `'npm'은(는) 내부 또는 외부 명령이 아닙니다`

Node.js가 없거나 VS Code를 다시 켜지 않았습니다.
Node.js 설치 → **VS Code 완전히 종료** → 다시 열기.

## `Error: Cannot find module ...`

`npm install` 을 안 했거나 중간에 실패했습니다. 6단계를 다시 하세요.

## `Port 3000 is already in use`

3000번을 이미 다른 프로그램이 쓰고 있습니다.
이전에 켜 둔 `npm run dev` 터미널이 남아 있을 가능성이 큽니다.

VS Code 터미널 창 오른쪽에 터미널 목록이 있습니다. 쓰레기통 아이콘으로 전부 지우고 다시 시작하세요.

또는 다른 번호로 켜기:

```bash
npm run dev -- -p 3001
```

이 경우 브라우저 주소도 `http://localhost:3001` 로 바꿔야 합니다.

## 브라우저에 아무것도 안 뜨고 흰 화면

1. 터미널에 `Ready` 가 떴는지 확인
2. 주소가 `http://localhost:3000` 이 맞는지 확인 (`https` 아님)
3. 브라우저에서 `F5` 로 새로고침

## 터미널에 빨간 글씨가 계속 올라감

당황하지 말고 **맨 첫 줄**을 읽으세요. 나머지는 대부분 그 줄의 부연 설명입니다.
`Error:` 로 시작하는 줄을 그대로 복사해서 검색하거나 팀에 물어보면 됩니다.
